# KDiag v0.4.1 — Permission Visibility & Bilingual Console

v0.4.1 is the published release for the permission visibility and bilingual
console work. It supersedes v0.4.0 and preserves UTF-8 source text in the
GitHub tree and generated artifacts.

## Implemented

- Read-only Kubernetes permission checks for every collected resource kind.
- A user-facing permission matrix with generated, copyable RBAC YAML and
  `kubectl apply` guidance. KDiag never grants itself permissions.
- Explicit `healthy`, `warning`, `critical`, `observed`, and `unknown` resource
  states. Successfully collected resources without a universal Kubernetes
  health condition are shown as observed instead of unknown.
- Chinese and English console languages with persisted preference.
- Bilingual navigation, inventory, overview, diagnosis, network diagnosis, and
  permission settings.

## Validation

- Go tests and vet passed.
- Frontend lint, typecheck, tests, and production build passed.
- Helm lint and template validation passed.
- Secret scanning and reachable Go vulnerability scanning passed locally.
- Live three-node cluster verification reported 260 resources, all with an
  explicit state, and 20/20 configured resource permission checks allowed.

## Security

- Generated RBAC remains read-only (`get`, `list`, and `watch`).
- Secret resources and Secret contents remain excluded.
- The product displays and copies authorization guidance but never applies it.
- Active probes remain disabled by default.

## Known limitations

- `observed` means collection succeeded but the resource kind does not expose a
  universal health condition; it is not equivalent to healthy.
- English localization prioritizes navigation and diagnosis workflows; raw
  Kubernetes values, resource names, and historical saved Chinese evidence are
  not machine-translated.
- The production Web bundle still needs route-level code splitting.
