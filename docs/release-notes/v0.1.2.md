# KDiag v0.1.2

This patch release fixes the Helm deployment of the KDiag Web console when the
recommended read-only root filesystem security setting is enabled.

## Fixed

- Added a writable `emptyDir` mount for Nginx runtime configuration at
  `/etc/nginx/conf.d`.
- Kept the Web container root filesystem read-only and retained the existing
  non-root security context.
- Updated the Helm Chart and default image tags to `v0.1.2`.
- Updated the release workflow to select release notes by tag.

## Validation

- Helm lint passes.
- API and Web deployments were exercised on Kubernetes 1.28.
- The Web console returned HTTP 200 through a NodePort.
- The proxied `/api/v1/health` endpoint returned `status: ok`.

## Security

- Active probes remain disabled by default.
- Kubernetes RBAC remains read-only.
- No credentials are stored in the Chart or container images.

## Known limitations

- PostgreSQL must be provided separately and referenced through a Kubernetes
  Secret. Without `KDIAG_DATABASE_URL`, the API uses its in-memory repository.
- NetworkPolicy analysis does not prove end-to-end CNI data-plane reachability.
