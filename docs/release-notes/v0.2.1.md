# KDiag v0.2.1 — Live resource workflows

## Implemented

- Diagnosis, network tracing, topology, namespace, and replay inputs now use
  live selectable data instead of manually entered resource names.
- Selectors refresh every 15 seconds and show loading, error, and empty states.
- Added working policy and alert, report center, resource topology, and system
  settings pages.
- Network diagnosis now constructs its structured snapshot from current
  Kubernetes inventory in the Web console.

## Demo

Open the Web console, choose **资源诊断** or **网络诊断**, then select a
Namespace and resources observed from the connected cluster. Use **资源拓扑**
to inspect current ownership and relationship edges.

## Verification

- Go unit/API/SSE tests
- Frontend lint, typecheck, Vitest, and production build
- Helm lint and rendered manifest validation
- Repository secret and dependency security checks

## Known limitations

- Live inventory covers 20 common built-in kinds and does not auto-discover
  arbitrary CRD instances.
- Static NetworkPolicy analysis cannot prove CNI dataplane behavior.
- Direct network-diagnosis API clients still provide the structured snapshot.
- The application has no built-in user authentication; deploy it behind an
  authenticated proxy for production use.

## Security

KDiag remains read-only, never watches Secrets, disables active probes by
default, and does not expose arbitrary command execution.
