# KDiag v0.3.1 — targetPort validation patch

This patch follows the v0.3.0 explainable diagnosis experience release.

## Implemented

- Keeps the targetPort demo backend healthy with a non-root BusyBox HTTP server and a TCP readiness check.
- Shows the exact Service port, current targetPort and backend-declared container ports.
- Produces a read-only targetPort diff instead of placeholders.
- Uses the real Service UID in network reports so the local topology and Incident linkage are retained.

## Validation

- Go unit, API and network tests passed.
- `gosec` passed.
- The isolated `kdiag-targetport` scenario reached a Ready Endpoint and KDiag confirmed `target_port_mismatch`.

## Security

- Active probes remain disabled by default.
- KDiag does not apply the suggested change.
- The demo workload runs as UID 65534, drops all capabilities and disallows privilege escalation.

## Known limitations

- NetworkPolicy analysis remains static without CNI flow data.
- Active probes require an explicit allowlisted configuration.
- Automatic long-running Event-to-Incident materialization is still planned; confirmed interactive diagnoses create Incidents.
