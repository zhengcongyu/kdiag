# KDiag v0.2.0 — Live Cluster Panorama

## Implemented

- Automatic Kubernetes connection through in-cluster ServiceAccount credentials
  with standard kubeconfig fallback for local execution.
- Informer/List-Watch inventory for 20 common cluster, workload, network,
  storage, configuration, policy, and Event resource kinds.
- Live cluster overview, filtered inventory, and detailed resource REST APIs.
- iOS-inspired Cluster Panorama with group, namespace, state, node, label, and
  keyword filtering.
- Structured health wording, ownership and Service/EndpointSlice/Pod
  relationships, related Events, and a sanitized raw-object inspector.
- Read-only RBAC expansion for the supported resource kinds without Secret
  access.

## Demo

Deploy the Helm chart and open the Web Service:

```bash
helm upgrade --install kdiag deploy/helm/kdiag -n kdiag --create-namespace
kubectl -n kdiag port-forward svc/kdiag-kdiag-web 8088:80
```

Open `http://localhost:8088`, then use **Cluster Panorama** to filter and inspect
resources.

## Known limitations

- The live inventory covers 20 common built-in resource kinds; arbitrary CRD
  instances are not auto-discovered.
- Some resource kinds are intentionally marked unknown until a deterministic
  health classifier exists.
- Related Event visibility is bounded by Kubernetes Event retention.
- Network diagnosis still does not prove CNI dataplane health without traffic
  evidence.
- Built-in authentication and multi-tenant authorization are not included;
  deploy behind an authenticated proxy or identity-aware ingress.

## Security

- Secrets are not present in the inventory RBAC and are never watched.
- Defense-in-depth redaction removes Secret payloads and sensitive annotations.
- Access remains read-only; active probes are disabled by default.
