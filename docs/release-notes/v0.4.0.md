# KDiag v0.4.0 — Permission visibility and bilingual console

## Implemented

- Effective Kubernetes `get/list/watch` permission checks for all 20 configured resource kinds.
- Partial informer startup: a denied kind no longer prevents authorized kinds from being collected.
- A permission matrix in Settings with per-verb results.
- A manually reviewed read-only RBAC manifest generator. KDiag never applies the manifest itself.
- Separate `observed` status for resources that are visible but have no universal health condition.
- Structured state summaries for Namespace, ConfigMap, CronJob, Ingress, NetworkPolicy, StorageClass, HPA, and PDB.
- Persistent Chinese and English selection across primary cluster, diagnosis, network, report, and settings experiences.

## Security

- Secret resources and content remain excluded.
- Generated RBAC contains read-only `get/list/watch` permissions plus self-access review only.
- No automatic privilege escalation or workload mutation was added.
- Active probes remain disabled by default.

## Verification

- Go unit, API, inventory, collector, diagnosis, and network tests.
- Frontend lint, typecheck, Vitest, and production build.
- Helm lint and rendered manifest review.
- Dependency audit, gosec, and secret scan.

## Known limitations

- An object marked `observed` is readable but does not have a universal Kubernetes health condition; it is not presented as healthy.
- Permission changes require an API Pod restart or redeployment because informer scope is selected during startup.
- Some diagnosis content originates from saved reports and may remain in the language used when the report was created.
