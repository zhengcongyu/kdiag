# KDiag v0.3.0 — Explainable diagnosis experience

## Implemented

- The API builds diagnosis observations from the live informer inventory;
  browsers and CLI clients only select a target.
- Reports lead with a Chinese plain-language conclusion, impact, blocking
  point, root cause, safe remediation, and post-fix verification.
- Checks are grouped into confirmed problems, suspected problems, healthy
  checks, and unverified checks. Missing data is never presented as healthy.
- Network diagnosis shows every path layer and marks the first blocker plus
  downstream checks that could not run.
- The topology workspace is a real interactive React Flow graph with health
  labels, relationship arrows, fault-chain focus, depth, and direction.
- Diagnosis reports are refreshable, persisted, listable, and exportable as
  Markdown or JSON.

## Demo

1. Open `/diagnose`, select a live resource, and start automatic diagnosis.
2. Open `/network`, choose a source, Service, and port.
3. For the targetPort lab, use the existing manifest under
   `deploy/kind/scenarios/targetport` and confirm that the result says the path
   is blocked at the target port.

## Verification

- Go unit and API tests cover trusted observation building, report
  classification, SSE, topology, deterministic rules, and network faults.
- Web tests cover resource selection and the plain-language report.
- Frontend typecheck, lint, tests, and production build are release gates.

## Known limitations

- NetworkPolicy analysis is static and cannot prove CNI dataplane behavior.
- Active probes remain disabled unless a separately privileged allow-listed
  runner is configured.
- The automatic long-running Event-to-Incident controller is not yet wired;
  confirmed interactive diagnoses create Incidents and all tasks remain in the
  report center.

## Security

- KDiag remains read-only and does not collect Secret content.
- Browser-supplied observations or network snapshots are not trusted.
- Suggested changes are previews only; KDiag does not mutate production
  resources.
